Keep reports private, preserve observed failures, and remove the disposable instance after verification; see README development instructions.

The default uses one CPU thread per inference lane: foreground recall can run alongside one background encoder without waiting for a whole long document or oversubscribing the two-CPU quota. Mutable model preprocessing remains serialized; float32 precision, prompts, revision and dimensions are unchanged. Keep `OMP_NUM_THREADS=1` under this resource budget; raising it can cause automatic recall to miss its deadline during indexing. On a larger CPU allowance, `MEMENTO_BACKGROUND_TEXT_THREADS` (1..8, default 1) raises intra-op threads for the background text session only; foreground recall keeps its own one-thread session. `MEMENTO_TEXT_SCORER_THREADS` (1..8, default 1) separately raises the foreground recall text scorer's intra-op threads for a larger local allowance; keep 1 on two-CPU or shared hosts (a later Contabo move is resource-strained) and set it only in machine-private configuration. Measure recall latency and complete indexing throughput before changing it on a deployment.

Explicit text is tokenized literally, including model control-token spellings; image/audio preprocessing remains native. A one-time text-encoding upgrade re-encodes only affected legacy text vectors without changing raw history, vector IDs or ordinary text/media vectors. It makes affected failed units due again; only successful normal indexing resolves those failure records. Passage chunking uses the same literal-token mode under the shared preprocessing lock.

Shutdown finishes the current indexing unit, commits completed vectors and leaves the rest pending instead of draining a whole batch before exit. Restart resumes that unfinished work.

The seven ordinary memory tools are `recall`, `remember`, `link`, `supersede`, `reconcile`, `history`, `loop`; the eighth MCP tool, `work`, exposes the common authorized processing contract. Explicit saves require nonempty verbatim quotes (zero-based `occurrence` for repeats), never invented evidence; native hooks resolve current-conversation provenance. Mutations require stable `command_id`, `actor`, `why`; reuse a command ID only for an identical retry. `remember`/`supersede` scopes are `["personal"]`, `["professional"]` or both. `supersede` appends the next content version under the same memory ID and distinguishes correction, supported refinement and world-time change (the latter requires aware `valid_at`); `history` preserves versions/diffs/reasons/evidence. `recall(query, effort="cheap|normal|deep", scope=...)` is semantic; omit query for recent raw activity, or use `since` (aware ISO time)/`source` for literal raw evidence filtering (raw evidence has no inferred scope). Exact source text/artifacts and time/page offsets are retained. `loop` supports `list|open|close|later|remind|assign|decline`; only explicit `remind` sets a reminder time, with no proactive scheduler.
Explicit duplicate requests use `reconcile` / `POST /reconcile`: read current history, establish identity from evidence, supply survivor/absorbed IDs, exact member versions and original premises for every member. Reuse normal coalescence to preserve aliases, connections, loops and history; never construct synthetic candidates or route routine merges through the owner console. Pins, sensitive types and different scopes retain the existing private review gate. No approval field or owner impersonation is available to agents.

Relation names are open-ended lowercase snake_case identifiers starting with a letter, at most 64 characters; built-in names are suggestions, never an allowlist. Choose the most specific source-supported directional predicate, reuse an existing equivalent meaning, and never infer kinship or identity from names. No predicate registration is needed; `supersedes` remains reserved for atomic supersession.

Loop responsibility is generic `owner|other|unknown`, displayed as For owner / Other person / Unspecified and filterable in the viewer and `loop(list)`. Personal scope never implies owner responsibility. Exact original native user evidence, or a native assistant's direct question asking the owner for a lasting choice, must ground owner attribution; unknown remains explicit. `loop(assign, responsibility, evidence)` changes only role, retaining dates/state/deferral and manual attribution through identity transfers. Grounded `loop(close, evidence)` requires original completion time newer than pending evidence and manual choice; `loop(decline, evidence)` retracts only an unprotected untouched automatic marker using original premises. These operations support nodes, relations and candidates, preserve raw history and report protected/unknown chronology without closing. Empty-evidence close retains the existing explicit manual operation. Role-only assignment never reaffirms a pending obligation or moves its manual chronology boundary.

Automatic role proposals use the eligible original source subset. If no qualifying evidence supports attribution, preserve the existing role or leave a new loop unknown without rejecting otherwise valid memory work. Direct assignments, fact/quote validation, forgetting, pins and manual choices retain their strict guards.

Native and MCP tools treat empty optional strings, including `recall.effort`, as omitted; required text/reasons/quotes and nonempty invalid dates still fail validation. HTTP commands remain strict.

Stored-memory period recall uses additive aware-ISO `memory_since` (inclusive) / `memory_until` (exclusive), with or without a semantic query. Supplied homonyms and semantic equivalence remain the model's judgment.

Bounded `repairs` in the same consolidation plan can absorb evidenced same-referent entities or equivalent claims, supersede an existing assertion, or curate supplied loops without fabricated candidates. Automatic claim coalescence preserves type, exact scope, validity and behavioral authority; protected records produce ordinary review proposals. A supersede revises the same memory ID and keeps its links; refinement retains prior premises, and a correction or world change retires only the named supplied relations (`retire_relations`) whose evidence shows a mistaken referent or ended state. Plans operate only on supplied, version-fenced nodes and exact original sources. The same commit repairs bounded orphan relations left on proven refined/merged ancestors of supplied current identities; it fences old versions, selected edges, collision absence and loop choices. Unfenced destinations and remaining adjacency continue through the same durable groups; corrections and world changes are excluded. Narrow `retire` repairs can remove source-proven retrieval bookkeeping or temporary task scaffolding from active memory without inventing a replacement; they preserve assertion/edge versions, evidence and raw sources. They require complete incident-edge/loop fences and preserve protected choices. Retirement is derived-memory maintenance, not the owner-only forget operation and not suppression of source history.

For explicitly selected existing subjects, private `POST /work/maintenance` accepts stable `command_id`, `actor`, `why`, one to 48 distinct active visible `target_ids`, and optional `origin`. It persists an idempotent repair group; pending requests with the same sorted seeds share a group. Normal touched-subject plans can request bounded `continue_with` seeds. Durable frontier/reviewed state survives restart, window closure and failed jobs; unchanged context cannot request itself forever. Groups and new candidates alternate admission through the existing consolidation jobs, lease fence, runner and configured night window, with no second daemon or whole-graph nightly inventory. A permanently failed repair job leaves its group pending and waits a 15-minute cooldown before rederivation. Status reports global pending/done repair-group counts; done means the supplied bounded work was inspected, not proof of semantic completeness. Seeding does not reopen parked conversation history, and startup seeds nothing. Recall also queues visible same-spelled durable anchors and identical-text durable memories that automatic recall collapsed for this worker; pending candidates and media remain excluded.

Existing nodes and relations enter the consolidation input as their assertion text plus exact evidence references (episode, quote, offsets, occurrence, original source time, source/kind, conversation/event/native identity and ground-truth flag) without a surrounding ±400-character raw window; candidate evidence and the bounded technical trace keep their windows. A plan may cite such a reference as the exact supplied quote or any verbatim subspan fully inside that supplied range of the same episode, or anywhere inside a supplied raw window, never text beyond the supplied quote; `source_span` still validates every quote against the immutable source, and the original candidate source remains required. A changed consolidation policy invalidates older leases for fresh preparation. This reduces request bytes, not server source reads (occurrence and ground-truth checks still hydrate the episode), and removing surrounding context does not preserve every comparison judgment the model previously had. An existing reference whose episode is a native attempt/result projection also carries its source, conversation, sequence and `native_trace` marker, so an already-supplied exact attempt or result beyond the nearby trace bound can still be named in `technical_evidence` for an inferred lesson; the same one-conversation, latest-attempt-before-result, original-source and exact-span rules apply, no surrounding text is restored, and references from contexts leased before this metadata existed carry no trace.

Ordinary evidence-backed `person` memories, their corroborations, relations and supersessions consolidate automatically under the same evidence and identity checks; pins, sensitive custom types, new types, protected identity operations and unresolved identity ambiguity still require review. An undecided legacy create-person review from the former blanket person gate is stale: its candidate is derived again against current memory, approval is refused, and rejecting it never rejects that candidate.

After background compression, the human/service owner can run `docker compose exec memory /usr/local/bin/memento-admin --data-dir /data compact` to reclaim free pages in the existing database. This uses the owner socket, with no additional confirmation prompt, archive or Drive I/O. SQLite scratch is private on the persistent data volume; allow free space roughly twice the database size. The service writer mutex remains held for VACUUM and its checkpoint, so foreground operations may time out and native capture stays queued. Do not restart to clear the temporary wait. Ctrl+C disconnects the admin client without cancelling the server operation. The result reports before/after database and WAL bytes, free pages and checkpoint status; a busy checkpoint returns incomplete/nonzero. Preserve logical history, vectors, FTS, implicit row identities and consolidation cursors. Qualify physical compaction on both supported host and image SQLite before changing this path.

Recovery on a separate host, as intended service owner, with a human-provided private connection:
```sh
/usr/local/bin/memento-restore --connection /private/drive-oauth.json
/usr/local/bin/memento-restore --connection /private/drive-oauth.json --backup-id ID --destination /private/empty-recovery
```
The first lists verified backups; the second restores database plus available hot artifacts to an empty private directory. Incomplete snapshots are refused unless explicitly adding `--allow-incomplete`; inspect the gap manifest. Keep the original Desktop OAuth client securely off-box; after disk loss re-consent that same client to recover app-scoped access. Drive copies are plaintext, retained versions consume quota, and local data/credential ownership must be restored before starting Compose.

### Database export and host migration

Owner-only `memento-admin --data-dir DIR export --output FILE` exports a consistent database, its **existing Drive references, and only locally stored payloads without a verified remote copy** into one private plaintext archive. Never download or repack Drive-resident files for export. Inclusion follows `remote_id IS NULL` in the snapshot, not hot/cold tier or cache presence; missing/corrupt required local bytes abort. It uses the existing owner Unix socket and human terminal confirmation, never an HTTP/MCP export route. Output parent must be private; output is `0600` and never overwritten. Use `/data/exports` or another persistent data-volume directory, not `/tmp` tmpfs. Copy out with `docker compose cp`, verify checksums, then remove only the verified in-volume copy.

The `memento export` and `memento restore` frontdoors delegate to these existing owner/export and restore engines. They preserve the same ownership, confirmation and empty-destination requirements.

`memento-restore --archive FILE --destination EMPTY` restores the database without an active Drive grant. Version-2 archives retain remote IDs and the original non-secret account/folder/public-client binding; restore prints the connection identity. Referenced Drive files become readable after reconnecting that original binding. Included local-only payloads remain hot; referenced payloads become cold, without downloading them. Manifest checksums, exact local-only payload coverage, SQLite integrity and foreign keys are validated in private staging before atomic publication; nonempty/live/symlink targets and unsafe members are rejected. Existing host transfer/failure/backup records are reset, not graph/raw/version/vector/audit history. Credentials, native configs and models are excluded. Version-1 self-contained archives retain their previous restore behavior: all payloads local/hot and old remote IDs cleared.

Preserve the restored owner-private `drive-binding.json`: it records only the expected account, folder and public client ID. Do not substitute another binding or infer the instance directory from an external credential-file path. Configure/one-link and startup use their existing explicit data directory; standalone `memento-drive connect` must receive `--data-dir RESTORED_DIR` for a restored instance. Export must refuse remote references without original binding metadata; it must not recover them by downloading Drive files.

Ctrl+C exits the admin client but does not cancel its server export. Normal completion/failure cleans staging; a service kill can leave `.memento-export-*` in the output directory. Remove only the exact task-owned staging after its producer is stopped, never the live database or Drive objects.

For fresh Compose recovery, **import before first startup**, as service UID, into `/data/instance` on the empty data volume using `docker compose run --rm --no-deps --entrypoint /usr/local/bin/memento-restore -v /private/memento.tar:/import/memento.tar:ro memory --archive /import/memento.tar --destination /data/instance`. The archive must be privately readable by UID 10001. Then use a persistent Compose override mounting `./data/instance:/data` before `up`; the README contains the exact override. Do not restore over a started instance or atomically rename the mounted `/data` root.

Migration is a point-in-time move, not sync: before the final export disable the old host's Memento Serve route, stop its processor timer and wait for any running tick, and close its native sessions to stop loopback uploads. Remote clients spool durably. Keep the old service running for owner export, then stop it before enabling the new instance/repointing clients; never accept writes on both. Retain client identities so queued captures upload to the new host, configure one processor, and separately reconnect optional Drive with the original client/account/folder. Another-server deployment still requires explicit authorization.
