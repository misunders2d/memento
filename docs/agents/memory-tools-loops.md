# Memory tools, relations and open loops

Detail for [AGENTS.md](../../AGENTS.md). Caveman-compressed; every rule here is binding.

Committed citation usage + query feedback follow promotion, correction, reviewed merges atomically, without separate assertion versions or changes to raw evidence.
Seven ordinary memory tools: `recall`, `remember`, `link`, `supersede`, `reconcile`, `history`, `loop`; eighth MCP tool, `work`, exposes common authorized processing contract. Explicit saves require nonempty verbatim quotes (zero-based `occurrence` for repeats), never invented evidence; native hooks resolve current-conversation provenance. Mutations require stable `command_id`, `actor`, `why`; reuse command ID only for identical retry. `remember`/`supersede` scopes: `["personal"]`, `["professional"]` or both. `supersede` appends next content version under same memory ID; distinguishes correction, supported refinement and world-time change (world-time change requires aware `valid_at`); `history` preserves versions/diffs/reasons/evidence. `recall(query, effort="cheap|normal|deep", scope=...)` is semantic; omit query for recent raw activity, or use `since` (aware ISO time)/`source` for literal raw evidence filtering (raw evidence has no inferred scope). Exact source text/artifacts and time/page offsets retained. `loop` supports `list|open|close|later|remind|assign|decline`; explicit `remind` sets manual due date, processing sets automatic one only from explicit source date (owner amendment 2026-11-01, below); no proactive scheduler or notification.
Explicit duplicate requests use `reconcile` / `POST /reconcile`: read current history, establish identity from evidence, supply survivor/absorbed IDs, exact member versions and original premises for every member. Reuse normal coalescence to preserve aliases, connections, loops, history; never construct synthetic candidates or route routine merges through owner console. Pins, sensitive types, different scopes retain existing private review gate. No approval field or owner impersonation available to agents.

Relation names: open-ended lowercase snake_case identifiers starting with letter, at most 64 characters; built-in names are suggestions, never allowlist. Choose most specific source-supported directional predicate, reuse existing equivalent meaning, never infer kinship or identity from names. No predicate registration needed; `supersedes` stays reserved for atomic supersession.

Loop responsibility: generic `owner|other|unknown`, displayed as For owner / Other person / Unresolved, no assignee, filterable in viewer and `loop(list)`. Only assigned (owner/other) loops are obligations (owner decision 2026-11-01): unfiltered `loop(list)` and viewer counts show them, report unresolved count separately; `responsibility=unknown` lists unresolved loops, which stay open until closed but are never obligations. Personal scope never implies owner responsibility. Exact original native user evidence must ground owner attribution; assistant questions never do (owner amendment 2026-11-18); unknown stays explicit. Text inside `[BEGIN UNTRUSTED …]…[END UNTRUSTED …]` blocks (chat front doors wrapping other people's messages, also mid-line) never counts as owner words, like `<pasted_content>`; unterminated opener runs to end of message. `loop(assign, responsibility, evidence)` changes only role, retaining dates/state/deferral and manual attribution through identity transfers. Grounded `loop(close, evidence)` requires original completion time newer than pending evidence and manual choice; `loop(decline, evidence)` retracts only unprotected untouched automatic marker using original premises. These operations support nodes, relations and candidates; preserve raw history; report protected/unknown chronology without closing. Empty-evidence close retains existing explicit manual operation. Role-only assignment never reaffirms pending obligation or moves its manual chronology boundary.

Automatic role proposals use eligible original source subset. If no qualifying evidence supports attribution, preserve existing role or leave new loop unknown without rejecting otherwise valid memory work. Direct assignments, fact/quote validation, forgetting, pins, manual choices retain strict guards.

Native and MCP tools treat empty optional strings, including `recall.effort`, as omitted; required text/reasons/quotes and nonempty invalid dates still fail validation. HTTP commands stay strict.

Manual open-loop housekeeping: batches of **10 loops**, **five-minute maximum per batch** for assigned subagent. Quickly inspect original evidence, do short grouped completion lookup when useful, then reconcile or assign generic owner/other/unknown responsibility. Loops track human obligations only (owner amendment 2026-10-31): AI assistant's or agent's own promise or next step, agent-to-agent orchestration, summaries restating pending steps are never loops and may be declined as automatic markers; only `owner` attribution needs native human ground truth. Loops cover only obligations between humans (owner amendment 2026-11-18): what owner owes another person, reminders owner explicitly sets for themself, what other people owe owner or others. Owner's promises or answers to agent, and agent's questions or approval requests to owner, are never loops. Missing completion evidence does not make known assignee unknown. Preserve uncertain and protected loops with one-line reason; report actual closures, retractions, assignments, blocked cases per batch, then proceed to next ten. Do not turn backlog sweep into open-ended historical investigation. This manual workflow does not change scheduled consolidation batch sizes or authority checks.

Open loops from extraction are tentative markers, not verified obligations. Consolidation reuses existing same-/cross-batch identity resolution for duplicates. `open_loop=false` declines only untouched extraction marker; `null` preserves uncertainty; neither overrides existing target's chosen state. Extraction retains explicit completion/cancellation of specifically identified outstanding obligation as lifecycle evidence, even without separate durable fact; consolidation can reject that candidate while using `closed_targets` to close same obligation. Closure requires exact evidence with known source time newer than pending evidence and manual choice. Existing-only `close_loop` repairs use same chronology check; `decline_loop` retracts automatic marker proven never to be concrete obligation, preserving manual choices (including `remind` due dates), pins, deferrals; automatic due date does not protect marker. Concurrent loop changes invalidate prepared plan. Identity coalescence retains manual-choice and closure chronology across every transferred branch, including occupied survivor. Automatic closure records its source-time boundary so later evidence can reopen; age, inactivity, sheer loop count never justify closing or deleting. Relevant waits on other people stay useful loops; assistant/agent self-commitments do not qualify. No new reminder scheduler or model pass added.

Automatic loop due dates (owner amendment 2026-11-01, replacing "only explicit `remind` sets a reminder time"; native service only, Python comparison service does not set them): extraction (`extract-v3`) and consolidation (`consolidate-v15`) may propose `due` for open loop only when cited quote explicitly states its date or deadline ("tomorrow", "by Friday", "on Nov 3", "end of month"); vague timing gives none; dates never invented. Model resolves relative dates against source's original `occurred_at`, supplied as `local_time` with weekday in claim's IANA timezone (stored in leased context); `due.quote` must be verbatim inside candidate's quote or consolidation premise from original candidate source, never `later_context`. Convention: calendar date `YYYY-MM-DD` means end of that local day (23:59:59, later instant if repeated; nonexistent local time refused), stated time is aware ISO timestamp, `loop_events.due_at` stores UTC-normalized value like `remind`. Validation rejects malformed/naive values, `due` without `open_loop` true, expressions absent from quote, dates before source time unless `overdue` says deadline had already passed (`candidate_due_*`/`consolidation_due_*`, with `previous_rejection` feedback). Manual `remind` anywhere in loop lineage, or live `later` deferral, always wins; otherwise newer explicit evidence may replace automatic due date under closure chronology rule (`closure_time`). Promotion and identity transfers carry it as they carry reminders. Stale pre-`extract-v3` extraction leases refused and rederived. "Due today/overdue" uses `loop(list, due_before=<next local midnight>)` / `due_before=<now>`. No backfill, scheduler, notification, table or filter added.

During historical uploads, quote-only native saves and quoted media saves flush matching eligible message projections without draining unrelated capture. Evidence with explicit episode ID needs no local flush. If generic tool wrapper bypasses native pre-tool hooks, set `CFG` to existing harness configuration and run `python3 "$(dirname "$CFG")/bridge.py" flush-conversation --config "$CFG" --agent HARNESS --conversation-id ID --quote 'Exact source quote'`, repeating `--quote` as needed, then retry identical save command. Result identifies acknowledged episodes and unmatched quote indices; unmatched local quote may already be on server, whose normal evidence validation still applies. Embedded tool-result blocks lacking derivable message key require ordinary upload. No-quote `flush-conversation` retains whole-conversation behavior.
