# Processing: work API, extraction, consolidation

Detail for [AGENTS.md](../../AGENTS.md). Caveman-compressed; every rule here is binding.

Pi processing: one persistent native RPC process with only `memento_work`, thin adapter to common HTTP `/work` API. Host qualifies complete active/all tool catalog before evidence, renews leases independently, owns cancellation. Agent discovers paginated pool metadata, picks consolidation batch sizes of 1–128 candidates (start 16), can commit/request fresh work together. Continuous admission fills requested size with whole conversations in candidate order: first always (at most the size); each following one only when all its pending candidates inside lookahead of twice the size fit remaining room; first that does not fit leads next batch. Context keeps current evidence, native reasoning/tool history within unfinished work, compact receipts, empty work kinds; prune completed work only after commit/release and redact lease capabilities. Rotate sessions after sixteen commits without restarting native process. Continuous claims admit newly eligible candidates only within configured night window or explicitly authorized force run. Existing quote/identity/loop authority checks unchanged. OMP/Claude keep legacy two-lane runner described below. All five harnesses can use same HTTP/MCP processing API; automatic Codex/AGY qualification stays separate. HTTP returns full packets; MCP claim descriptors require lossless `read` pages + separately cached policy/schema pages. See [shared processing contract](README.md#shared-processing-api-and-the-pi-worker). Roll out service before processing runner; optional hash-verified processor assets preserve existing five-file client release contract. Never restart a stopped unscheduled catch-up without owner authorization. Each `POST /work` claim, submit, complete or pool request writes one stderr `work_timing` line: action, outcome, per-stage microseconds (`claim_*`, `prepare_*`, `targets_*`, `complete_*`, `apply_*`), cheap counts (requested batch size, admitted/kept/deferred candidates, preparation levels, lexical lookups) only; never IDs, text or payloads.

Claim receipts expose per-kind `backlog.claimable` from queue eligibility, exclusions, consolidation window. Preserve availability across native session rotation; host must replace stale empty-kind state when a kind reopens. Failed claim preparation must release failing lease and return every undelivered lease to pending, without consuming an attempt or adding backoff; already committed work stays done. Existing-node evidence uses bounded founding/latest original sources; cursor-free batches can defer candidates whose top comparison targets do not fit 48-version ceiling. Use `src/memento/capacity.py` for deterministic status/receipt measurements; net queue changes + extrapolated ETAs are not proof of update quality or daily capacity. Completion keeps job's result, drops its leased input packet; after startup, bounded background pass clears packets that older completed jobs kept. Failed, pending, leased jobs keep theirs for retries.

`consolidate-v10` gives loop-flagged candidates up to eight later communicated user/assistant messages in same conversation: at most 1,500 characters per message, 8,000 per candidate, 24,000 per batch. Excluded: tool output, private reasoning, hooks, instructions, forgotten sources. `later_context` windows support closure only, never assertion premises or newer pending date. Candidate closes own obligation through own `closed_targets` with `open_loop: null`; original chronology + manual-choice protections still apply. Absent completion = uncertainty. Existing stored loops + completions outside this bounded window still need evidence-based reconciliation.

First-test sequence (use synthetic text, not secrets):
1. In real native conversation, state distinctive durable fact. Confirm raw capture via `GET /episodes/search?q=...`, then fetch `GET /episodes/{id}` for exact text/source/conversation/time.
2. Compact via harness's native compaction action, or leave conversation inactive 30 minutes. Compaction marks captured sequence boundary; inactivity processes through latest sequence. Client compaction only nudges server; server timer/tick drains due work. Server-side compaction also drains immediately.
3. On processing host run:
   ```sh
   python3 "$HOME/.local/share/memento/runner.py" --config "${XDG_CONFIG_HOME:-$HOME/.config}/memento/runner.json" tick --consolidate-now
   ```
   This single first-test flag bypasses only consolidation night window, not extraction eligibility, and does not alter schedule. Normal consolidation runs within server config's local-time window (default 02:00–07:00 in configured timezone); runner sends that window with each claim; service rejects malformed one before touching anything. Inspect `journalctl --user -u memento-runner.service` and candidate `history(id)` for exact quotes, source spans, requested/reported model, known usage; do not infer success from a timer firing.
   Tick prints exact backlog counts for pending extraction conversations, pending jobs, leased jobs—not estimated message counts. Each extraction call packs at most 64 windows and 48,000 projected source characters; long user text continues with exact overlap; tool output projected to 2,000 characters without changing raw history.
   Extraction admission alternates between oldest unfinished captured evidence and newest eligible conversation, so finite imported prefix progresses while recent conversations also get processing time. Order survives restart in existing job records; compaction/inactivity eligibility and retry identities unchanged.
   With legacy OMP/Claude runner, failed job retryable after 15-minute wait following its batch; unrelated work continues. Rejected consolidation batch keeps its job, payload, candidates for that retry while other ready candidates consolidate in separate batches; at most one consolidation leased at a time; one extraction may run alongside it inside same tick. Tick runs one lane per work kind: finished lane claims again for only that kind (`kinds` on `/work/claim`; claim with both lanes free omits the field) while other lane keeps running, excluding its own just-finished ID for the cooldown and the running lease. Partial-kind claim requires updated server: roll out server before designated runner; ordinary capture/recall clients need no update. Kind offered nothing is not asked again until some job completes, so idle lane never polls. Finished job's cooldown is stamped when coordinator harvests its lane, which can be up to one claim timeout after actual completion, so failed job waits at least the 15-minute retry interval. Native safety check runs once per tick, lazily after first lane's lease heartbeat is running; both lanes share its result; failed claim, rejected claim response or Ctrl-C cancels running lane, which releases its job and joins its heartbeat before tick exits. Still at most two native processes and one consolidation lease. Tick still exits nonzero if any attempt failed, even if later retry succeeded.
   Failed attempts emit JSON diagnostics to stderr/processor journal: job ID, work kind, error category, available HTTP status/allowlisted rejection code or safe cause. They exclude memory text, model output, URLs, arbitrary server error messages; use receipt to distinguish failures, never infer cause from backlog counts. Generic `service_rejected` or HTTP 422 is not a diagnosis: identify exact safe rejection reason and verify an affected retry before declaring recovery; unrelated successful batches are insufficient.
   When server rejects completed batch for validation code (invalid quote, grounding, coverage or reference errors), it keeps that fixed code, attempt number and at most three references (known candidate/window identifiers, operation, occurrence, at most 300 characters of model's own offending quote) privately inside job's leased context. Next claim of same job serves them as `previous_rejection` beside fresh input, marked as failed model output, not evidence; later rejection replaces them. HTTP responses, receipts, journals still carry only fixed code. On rejection nothing is committed, no extra model call made; native CLI/schema failures carry no feedback; old runners need no change.
   In that legacy runner, background `/work/claim` request waits up to 60 seconds because server prepares batch context inside it; renewal, completion, release, foreground commands keep existing 15-second bound. Failed claim exits with same generic `service_rejected` message after writing `stage: claim` receipt with same safe HTTP status or cause classification; not retried within tick; next timer run claims again.
4. In both originating conversation and second fresh native session call MCP `recall` for the fact; candidates must be visible as unconfirmed before promotion. Follow with `history(id)` to verify original evidence. Require actual capture/extraction/recall evidence separately for each harness, not just installed files.
5. For Pi/OMP automatic injection, ask fresh native session about synthetic fact without mentioning its answer or asking it to call memory tool. Verify answer cites same memory ID, evidence resolves to original conversation, injected context is not added to persisted raw history. Check capture, extraction, explicit MCP recall, automatic injection separately.

Status counts routine server rebatches separately as `rebatched_jobs`. After server rollout, run `memento agent update` on clients to attach offered query and shown IDs to matching citations.

Known complete legacy Codex `AGENTS.md` instruction envelopes (optional environment-context suffix), complete `<codex_internal_context source="goal">` runtime envelopes, native Codex developer instructions: kept as raw history, excluded from extraction + behavioral authority. Existing memories supported only by those instructions stay explicitly searchable, omitted from automatic context. Stored candidates whose only evidence is such instruction text: no longer admitted to consolidation, prepared into batch or completed from stale lease (that lease gets 409, rederives; all-excluded batch completes without model call). Their rows, IDs, raw history, explicit recall, indexing untouched; they receive no decision; candidate with any genuine evidence stays eligible. Status reports them as `excluded_legacy_candidates` next to `pending_candidates`/`ready_candidates`, which now count only what consolidation can admit: drop in those counts = exclusion, not model completion. Predicate decides developer + non-Codex rows from kind/source alone; reads bodies only for Codex user rows. Server handles this: no history re-import, no client update; genuine user/custom prose + other harness content stay eligible.

Extraction sends model only short window handles, message kinds, exact projected text. Leased server context keeps original window/episode IDs + offsets for strict quote validation and unchanged run/candidate identities. Existing in-flight leases using full window IDs stay valid; new leases require their supplied handles.

Consolidation keeps ordinary 16-candidate batch, 48-version context ceiling. Checks exact same-type spellings (case/whitespace only), typed lexical/name-head + same-type semantic hints, then connected claims. Each subject's comparison queue starts with every member candidate's top exact, lexical, semantic target before weaker head matches. Candidates sharing a discovered subject share comparison slots: two reserved, fair spare allocation up to eight before optional context. Hints discover comparisons, never prove identity. `remember` creating exact same-type spelling not supplied to plan: refused. Identity created after prepare needs fresh plan; truncated checking or changed spelling -> human review bound to colliding versions. When any of those versions later changes (merge, corroboration, pin or supersession), that undecided review can no longer be approved; its candidate rederived against current memory; stale proposal stays listed, not decided automatically. Supplied homonyms, semantic equivalence stay model's judgment.

Bounded `repairs` in same consolidation plan can absorb evidenced same-referent entities or equivalent claims, supersede existing assertion, or curate supplied loops, without fabricated candidates. Automatic claim coalescence preserves type, exact scope, validity, behavioral authority; protected records -> ordinary review proposals. Supersede revises same memory ID, keeps its links; refinement retains prior premises; correction/world change retires only named supplied relations (`retire_relations`) whose evidence shows mistaken referent or ended state. Plans operate only on supplied, version-fenced nodes + exact original sources. Same commit repairs bounded orphan relations left on proven refined/merged ancestors of supplied current identities; fences old versions, selected edges, collision absence, loop choices. Unfenced destinations + remaining adjacency continue through same durable groups; corrections, world changes excluded. Narrow `retire` repairs can remove source-proven retrieval bookkeeping or temporary task scaffolding from active memory without inventing replacement; preserve assertion/edge versions, evidence, raw sources, protected choices; require complete incident-edge/loop fences. Retirement is derived-memory maintenance, not the owner-only forget operation and not suppression of source history.

For explicitly selected existing subjects, private `POST /work/maintenance` accepts stable `command_id`, `actor`, `why`, one to 48 distinct active visible `target_ids`, optional `origin`. Persists idempotent repair group; pending requests with same sorted seeds share group. Normal touched-subject plans can request bounded `continue_with` seeds. Durable frontier/reviewed state survives restart, window closure, failed jobs; unchanged context cannot request itself forever. Groups + new candidates alternate admission through existing consolidation jobs, lease fence, runner, configured night window; no second daemon, no whole-graph nightly inventory. Permanently failed repair job leaves group pending, waits 15-minute cooldown before rederivation. Status reports global pending/done repair-group counts; done = supplied bounded work inspected, not proof of semantic completeness. Seeding does not reopen parked conversation history; startup seeds nothing. Recall also queues visible same-spelled durable anchors + identical-text durable memories that automatic recall collapsed for this worker; pending candidates, media stay excluded.

Existing nodes/relations enter consolidation input as assertion text + exact evidence references (episode, quote, offsets, occurrence, original source time, source/kind, conversation/event/native identity, ground-truth flag), without surrounding ±400-character raw window; candidate evidence + bounded technical trace keep windows. Plan may cite such reference as exact supplied quote or any verbatim subspan fully inside that supplied range of same episode, or anywhere inside a supplied raw window; never text beyond supplied quote. `source_span` still validates every quote against immutable source; original candidate source still required. Changed consolidation policy invalidates older leases for fresh preparation. This reduces request bytes, not server source reads (occurrence + ground-truth checks still hydrate episode); removing surrounding context does not preserve every comparison judgment model previously had. Existing reference whose episode is native attempt/result projection also carries its source, conversation, sequence, `native_trace` marker, so already-supplied exact attempt/result beyond nearby trace bound can still be named in `technical_evidence` for inferred lesson; same one-conversation, latest-attempt-before-result, original-source, exact-span rules apply; no surrounding text restored; references from contexts leased before this metadata existed carry no trace.

Ordinary evidence-backed `person` memories + their corroborations, relations, supersessions consolidate automatically under same evidence/identity checks; pins, sensitive custom types, new types, protected identity operations, unresolved identity ambiguity still require review. Undecided legacy create-person review from former blanket person gate is stale: candidate rederived against current memory, approval refused, rejecting it never rejects that candidate.
