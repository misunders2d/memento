# Behavioral and technical lessons

Detail for [AGENTS.md](../../AGENTS.md). Caveman-compressed; every rule here is binding.

Inferred technical lessons can use agent's own captured attempts + observed results, including repeated ineffective calls reporting no error followed by useful changed approach. Consolidation adds nearby native tool-call/result projections in sequence order: at most 32 inspected records per side; 12 added messages / 8,000 characters per candidate; 32 messages / 16,000 characters per batch; 2,000 characters per nearby message. Attempts use message tail with exact offsets so preceding thinking cannot hide call; results use prefix. Original evidence windows intact. Inferred-only fallback requires: exact supplied quotes including original candidate source, native provenance in one source/conversation, assistant tool-call projection, tool result after latest cited attempt. Candidate originating in assistant's own later report/advise tool call: plan names actual attempt + result episodes in optional `technical_evidence` (cited, unique, at most eight, inferred authority only); sequence rule then applies to that selection, report stays ordinary supporting evidence, so no acknowledgment output needed. Plans without field keep all-cited rule. Selection = model's semantic choice: validator checks provenance + order, not that selected episodes caused lesson. Explicit user preferences still need user ground truth. Structural checks prove provenance/order, not that alternative solved task: existing model must reject failure-only patterns, unrelated outcomes, tool instructions, unsupported assistant success claims. Causal correctness + resistance to misleading tool text = model judgments, not deterministic guarantees. Claude/Codex/Pi/OMP captured call/result projections support this path; AGY projection path unverified. Missing native call/identity markers or context beyond these bounds may prevent learning. Path reads no raw native records, so already-imported unprocessed histories work with compressed/offloaded raw storage: no re-import, cursor reset or replay of rejected candidates. No added model pass, schema or client update. Stale consolidation leases rederive under new policy with existing job identity; extraction identities unchanged.

Technical learning = best effort: bounded evidence not supporting reusable improvement -> retain useful ordinary incident with `behavior=null` or reject nonuseful material. Do not defer solely to reread unchanged technical trace. Later captured experiences go through existing pipeline; no new retry loop, cross-session synthesis pass or guarantee of complete detection. Inferred conduct keeps exact command, flag, option or argument of named tool when that mechanism is the improvement (`consolidate-v12`); generic advice alone not actionable.

Lesson subject links (`consolidate-v13`): each experience maintenance target (existing lesson) gets up to three active visible entity nodes whose full name is token-window contained (anchor tokenizer) in its text or behavior applicability/conduct; allocated after reserved comparison slots inside 48-version ceiling; listed as `named_entities`. Plans link existing lesson via repair link; same-batch candidate cannot be linked, so promoted new or refined behavior-bearing lesson naming unlinked entity seeds existing repair groups (`origin` `lesson-links`, eight lessons per group). Repair jobs carry no candidate actions, never seed. Backfill existing lessons via `POST /work/maintenance`, same origin, at most eight per request so each is a target. Entity anchors give up to two linked behavior-bearing experience neighbors connection slots ahead of `records::related` (unchanged).

Updated native clients queue separate skipped, evidence-ineligible receipt per fresh automatic offer containing behavioral suggestions: at most two memory IDs/versions + original emission time, no lesson text. Consolidation reads bounded same-source/conversation window, treats earlier offers as advisory context; exact original quotes + current-version checks still authorize changes. Receipt proves neither reception nor causal influence. Cached replays reuse original offer's receipt. Old clients and imported histories get no retrospective receipts. Use normal explicit `memento agent update HARNESS` with installation's config/options; existing integrations use updated bridge on next fresh offer, no session restart. Server update alone does not enable client receipts; older integration-definition changes still follow normal reinstall/reload instructions.
