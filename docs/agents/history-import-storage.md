# History import, historical pool, raw storage, status, health

Detail for [AGENTS.md](../../AGENTS.md). Caveman-compressed; every rule here is binding.

## Import histories on each origin device

Finish first-test sequence ([processing.md](processing.md)) before importing history.

After client/server setup there, keep that device's private config + stable generated `client_uid`; setup rerun preserves it. Select actual local history files/directories explicitly (no automatic discovery). Run all applicable commands, replacing example paths:
```sh
CFG="${XDG_CONFIG_HOME:-$HOME/.config}/memento/runner.json"
BRIDGE="$(dirname "$CFG")/bridge.py"
python3 "$BRIDGE" import-history /path/to/pi/jsonl-history --config "$CFG" --agent pi
python3 "$BRIDGE" import-history /path/to/omp/jsonl-history --config "$CFG" --agent omp
python3 "$BRIDGE" import-history /path/to/claude/jsonl-history --config "$CFG" --agent claude
python3 "$BRIDGE" import-history /path/to/codex/jsonl-history --config "$CFG" --agent codex
python3 "$BRIDGE" upload --config "$CFG"
```
Only complete JSONL records queued; directories recurse over `*.jsonl`. Repeat import with same origin identity/event content = idempotent; uploads retry durably. Do not copy histories/config identities across devices and claim cross-device deduplication.

Explicit `upload` drains until empty or transport error, prints JSON `pending`/`conflicts` counts (plus `rejected` when nonzero), exits nonzero if any remains. A terminal service refusal (HTTP 400/413/415/422) parks only that row as `rejected` with its class (`http_413` etc.) so later records keep uploading; the bytes stay in the outbox, never acknowledged. `status` shows `rejected` and `rejected_by_class`. Each explicit `upload` requeues rejected rows once (e.g. after a service update); a repeat refusal parks them again. Other failures record their class on the row and keep today's stop-and-retry behaviour. Native background upload keeps bounded runtime and reads new journal lines in bounded slices (2 MiB) interleaved with uploads, so a large journal suffix never delays queued records; the cursor resumes where a slice stopped. Large attachments on slow connections may need explicit `memento upload`; failed binary retries do not block later text uploads.

Failed uploads include sanitized `error` category, HTTP status, local outbox ID when available; never infer timeout from pending counts or healthy `/health` alone. Preserve that result + queued data, fix cause, then retry same upload without re-importing. Immutable conflicts need investigation, not repeated retries.

Explicit text upload requests: normal 15-second foreground command allowance. Background text requests keep two-second timeout + bounded hook runtime; changing foreground allowance adds no automatic retries.

Supported frontdoor: `memento import-history PATH --agent HARNESS`, then `memento upload --agent HARNESS` and `memento status --agent HARNESS`; keep `--config PATH` for custom installation. Matching default config reused, else harness config selected. Referenced attachments need explicit `--artifact-root DIR`; OMP blob references use its native blob directory. Native attachment import: up to 32 MiB per object; reports missing/unsupported material. Raw records stay lossless; opaque attachment bytes excluded from projected text processing. Ordinary hooks reconcile only current transcript; explicit imports/uploads use persisted file-change fingerprints for registered histories.

Import returns selected conversation IDs, queues existing compaction markers after their captured records -> that history eligible for extraction while live conversations continue. After upload reaches zero pending/conflicts, retain their `extraction.progress` boundaries from status. Later `cursor >=` retained `compact_through` proves prefix extraction; later capture, compaction or partial offset beyond that prefix does not invalidate it. Indexing + candidate disposition need separate evidence; consolidation keeps its night window. No import registry or second processing pipeline created.

**Historical pool (one-time cutover).** Owner can park current unprocessed backlog instead of spending model calls on all of it: `docker compose exec memory /usr/local/bin/memento-admin --data-dir /data history park` (owner socket only, like `compact`, no review prompt; `history status` read-only). One transaction: records activation; parks every conversation's remaining unextracted range `(cursor, parked_through]` with separate live cursor starting at boundary; fails pending/leased extraction inside those ranges + every pending/leased consolidation batch with `historical_parked` (late completion gets 409; status counts them as `parked_jobs`, not failures); parks every active undecided candidate; sets database header 3. Repeating is a no-op and never extends the boundary; there is no undo command. Images accepting only headers 1/2 refuse header-3 database; startup, export, restore never lower it; parking tables travel with database. Everything captured after activation, including delayed offline records of old conversations with old original dates, processes normally through live cursor; status shows `cursor`, `parked_through`, `live_cursor` on parked rows, so `cursor >= compact_through` still means prefix extracted. Parked candidates stay stored, searchable, in history (`parked_candidates` next to `pending_candidates`); they leave consolidation admission + primary automatic pool. Explicit cheap/normal recall + automatic context fall back to parked raw history only when no current fact or lesson matched (entity anchors alone do not block it): at most one parked candidate + one passage in automatic context, labelled `Unverified historical source <date>`, using existing chunk vectors, floor, literal FTS; scoped recall gets no raw; hooks, instructions, tool-call projections, forgotten sources never offered. Raw results carry stable chunk reference as `id` with `episode_id`, span evidence, `historical`; `history(chunk id)` resolves span. Citing parked chunk or candidate via existing `/usage` path queues one deterministic `extract/demand` job for exactly that span (repeat citations, crashes, retries resolve to same job; empty output completes it), releases cited parked candidate with its relation endpoints, never moves a conversation cursor; resulting candidates consolidate via ordinary pipeline + bounded native-trace context. Legacy episode-id citation demands only an episode of at most one extraction window; longer ones need chunk reference. Viewing episodes, UI or status queues nothing; viewer's unprocessed list labels parked conversations as not queued. No client update needed.

New skipped native records offload exact opaque runs of at least 64 KiB into existing artifact store. Explicit source/history reads reconstruct + checksum original outside writer lock; unavailable/corrupt source bytes fail explicitly. Offloaded raw JSON cannot be assertion evidence: cite its message projection with exact quotes + offsets. Existing inline evidence stays supported. Physical storage does not change event IDs, logical metadata or retry equality. These source artifacts promptly eligible for Drive; database exports include their bytes only while they lack verified remote copy.

Existing background worker losslessly compresses remaining skipped native records into conversation-local zlib frames inside SQLite, at most 256 KiB decoded bytes per frame. Legacy larger records span frames. Frame insertion + physical episode rewrite commit together; original text checksums, IDs, timestamps, metadata, evidence, retry equality unchanged. Message projections not rewritten. Source reads transparently hydrate + verify frames. No model call, Drive transfer or additional daemon. `raw_storage` reports remaining inline representation, compressed record count, original bytes, stored compressed bytes. Frame-aware code marks every database it opens, imports or restores with `user_version` 2 in same transaction as its physical upgrades; pre-frame images refuse that header at startup/export/import/restore instead of reading empty text, earlier frame-aware images refuse it too -> rollback targets must support both header 2 and compressed raw history. New code still reads version-1 databases + archives; unknown future headers fail before any mutation.

Status distinguishes local queue state, capture, indexing, extraction, consolidation candidates/jobs, media, Drive availability. Native-source counts under `service`; explicit artifact-save counts under `artifacts_service`. Counts use one read-only database snapshot so history scans do not hold capture lock; query CPU/I/O cost still grows with stored history. Zero consolidation jobs does not mean all candidates promoted; counts alone do not prove processor online. Status `indexing` counts global even in source-filtered status: per-request exact count visits every index unit, took minutes at millions of units, so one background exact count runs at most every five minutes on demand (`REFRESH_SECONDS`), status serves latest with `counted_at`/`age_seconds` (`counting` before first), readiness/error flags stay live. Each `GET /status` writes one stderr `status_timing` line, per-section microseconds only.

First startup without status covering index builds it transactionally from existing records; large histories can delay readiness. Keep free data-volume space for index + its WAL; account for temporary sort in Compose's `/tmp` tmpfs under service memory limit. Clients spool while startup completes. Later starts reuse index; backups + exports include its size. Older non-container SQLite versions keep exact counts but may not optimize indexed expressions as effectively. Capture metadata stays validated JSON; malformed legacy metadata fails build, not silently omitted.

Watch for `Building episode status index` and `Episode status index build completed in N seconds` in service logs. Health can fail and Docker can mark container unhealthy until completion. Do not restart during the build: interruption rolls back the transaction and the next start repeats it.

Raw-frame covering-index replacement also builds once at startup, logging `Building raw frame status index` and `Raw frame status index build completed in N seconds`; same wait + no-restart guidance applies.

Node full-text index is derived: one document per node identity, keyed by small `node_fts_documents` mapping that survives `VACUUM`. First start on existing database rebuilds it once from current version of every node inside same startup transaction, logged with timing; interruption rolls back to previous index, next start repeats rebuild. Node history, versions, evidence, vectors not rewritten. Unchanged-text new version (corroboration, pin, merge survivor) reuses node's existing vector row, no duplicate added; stale `current=0` node vectors written before this change stay in place, harmless. Lexical ranking statistics change because historical duplicate documents gone.

`/health` no longer takes application mutex: store probe opens own short-lived connection, takes + rolls back real writer transaction with 250 ms bounded busy wait; retrieval check reads one WAL snapshot. Health therefore reports writer contention beyond that bound as unhealthy instead of waiting behind capture, and stays bounded while long foreground or background work holds mutex. Probe racing closing store can still report unhealthy; nothing written. Health also stays `503` after evidence writer mutex poisoned (`Evidence writer requires recovery`) or any background thread, job worker or Drive cold worker ends before shutdown, usually by panic (`Background service stopped; restart required`). Neither clears itself: inspect service log for the panic, then the human/operator restarts the container.

`artifact_storage` explicitly global even in source-filtered status: counts registered, local-only, verified-remote objects/bytes, not cache residency, eligibility or queued work. Existing Drive worker drains full bounded batches immediately, checks shutdown between batches; idle + failed work keep existing waits/backoff.
